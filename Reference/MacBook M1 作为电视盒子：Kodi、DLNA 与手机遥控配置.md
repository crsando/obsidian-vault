## 使用目标

将旧款 **MacBook M1** 通过 USB-C/HDMI 连接电视，长期运行 **Kodi**，并实现：

- iPhone 上的腾讯视频、爱奇艺等 App 向 Kodi 投屏；
- iPhone 作为 Kodi 遥控器；
- 手机远程关闭和唤醒电视画面；
- Mac 只关闭显示器，不自动进入系统睡眠；
- 唤醒后尽量直接回到 Kodi，不再次登录。

## 硬件与基础设置

- 使用支持目标分辨率和刷新率的 USB-C 转 HDMI 线或扩展坞，例如 **4K 60 Hz**。
- 合盖运行通常需要连接电源，并有外接显示器及键盘/鼠标或等效输入设备。
- 长期插电可在 macOS 中启用“优化电池充电”，或使用电池充电上限工具，将电量维持在约 70%～80%。
- 在“系统设置 → 显示器”中调整分辨率、缩放和刷新率。
- 在控制中心确认音频输出设备为电视、回音壁或 HDMI。

## Kodi 配置为 DLNA / UPnP 接收端

### 1. 显示高级设置

进入“设置 → 服务”，点击左下角的设置级别，切换至“高级”或“专家”。

### 2. 开启 UPnP / DLNA

进入“设置 → 服务 → UPnP / DLNA”，启用：

- **启用 UPnP 支持**；
- **允许通过 UPnP 远程控制**。

如果只需要接收投屏，不需要把 Mac 上的媒体提供给其他设备，“共享我的媒体库”可以不打开。

> [!important]
> Kodi 可以作为 UPnP/DLNA 播放器，但腾讯视频、爱奇艺等 App 的“TV 投屏”不一定使用完全通用的 DLNA 协议。设备能否被发现、视频能否播放以及清晰度是否受限，取决于 App 版本、版权策略和具体视频源。Kodi 搜不到或播放失败时，可改用 Mac 端网页/客户端，或使用专门的 DLNA 接收软件。

### 3. macOS 网络权限

进入“系统设置 → 隐私与安全性 → 本地网络”，允许 **Kodi** 访问本地网络。

如果启用了 macOS 防火墙，在“系统设置 → 网络 → 防火墙 → 选项”中允许 Kodi 接收传入连接。

### 4. 局域网条件

- iPhone 和 Mac 必须位于同一局域网，通常应处于同一子网；
- 不要让其中一台设备连接访客网络；
- 路由器或无线 AP 不应启用客户端隔离、AP 隔离；
- 2.4 GHz 与 5 GHz 通常可以互通，不要求使用同一频段，但部分路由器会隔离不同频段。

### 5. 路由器 UPnP 不需要开启

Kodi 的 **UPnP/DLNA** 用于局域网设备发现和媒体控制；路由器中的 **UPnP IGD** 主要用于自动创建公网端口映射。局域网投屏不依赖路由器的 UPnP 端口映射，因此无需为此开启。

## 配置 iPhone 遥控 Kodi

推荐使用 **Official Kodi Remote** 或 **Sybu for Kodi**。

### Kodi 端

进入“设置 → 服务 → 控制”，启用：

- **允许通过 HTTP 远程控制**；
- **允许本系统上的程序控制 Kodi**；
- **允许其他系统上的程序控制 Kodi**。

常用参数：

- 端口：`8080`；
- 用户名：自行设置，例如 `kodi`；
- 密码：建议设置一个仅用于家庭局域网的独立密码，不要复用 macOS 登录密码。

### iPhone 端

1. 打开 Official Kodi Remote 或 Sybu；
2. 优先使用自动发现；
3. 自动发现失败时，手动填写 Mac 的局域网 IP、HTTP 端口、用户名和密码；
4. 建议在路由器中为 Mac 配置 DHCP 地址保留，避免 IP 变化后遥控器失联。

Sybu 主要控制 Kodi。其电源菜单向 Kodi 发送系统命令，但在 macOS 上能否真正执行睡眠或关机取决于 Kodi 版本及系统权限，不适合作为唯一的 Mac 电源控制方案。

## 实体遥控器按键映射

2.4 GHz 飞鼠、蓝牙遥控器或键盘通常可以直接使用方向键和确认键。需要改键时：

1. 进入“插件 → 从库安装 → 程序插件”；
2. 安装 **Keymap Editor**；
3. 打开插件，进入 `Edit`；
4. 在 `Global` 或 `Fullscreen Video` 中选择要映射的动作；
5. 选择 `Edit key`，在倒计时内按下遥控器按键；
6. 返回并选择 `Save`。

Mac 的 HDMI 输出通常不能直接接收电视遥控器发出的 HDMI-CEC 指令。如需使用电视原装遥控器控制 Kodi，需要额外的 USB-CEC 适配器，并确认 macOS 与 Kodi 的兼容性。

## 用 iPhone 快捷指令关闭和唤醒屏幕

### Mac 端开启 SSH

进入“系统设置 → 通用 → 共享”，打开“远程登录”，只允许指定用户访问。

建议为 Mac 设置固定局域网 IP，并在 iPhone“快捷指令”中使用密钥认证；若使用密码，不要把可导出的快捷指令分享给他人。

### 关闭显示器

在 iPhone 快捷指令中添加“通过 SSH 运行脚本”，执行：

```bash
pmset displaysleepnow
```

该命令关闭的是 macOS 的显示输出，连接的显示器会一起休眠。macOS 原生命令不能单独选择某一台外接显示器。如果 MacBook 已合盖，当前有效显示器通常只有外接电视。

### 唤醒显示器

通过 SSH 执行：

```bash
caffeinate -u -t 2
```

`-u` 声明一次用户活动，`-t 2` 让该声明保持 2 秒。它可以唤醒显示器，但前提是 Mac 主机仍然清醒且 SSH 可连接。

> [!warning]
> 如果 Mac 已进入系统睡眠，SSH 命令无法连接。此时需要键盘、鼠标、USB 遥控器、支持的网络唤醒方式，或先避免主机自动睡眠。

## 只灭屏，不让 Mac 自动睡眠

“显示器睡眠”和“系统睡眠”是两个不同状态。作为长期插电的电视盒子，可以只在交流电源模式下禁止系统自动睡眠：

```bash
sudo pmset -c sleep 0
```

是否还需要调整 `standby`、`autopoweroff` 等参数，应先查看当前配置：

```bash
pmset -g custom
```

不建议在不了解影响时一次性关闭所有低功耗机制。`pmset -c` 只修改接交流电源时的配置，比同时修改电池模式更适合该场景。

恢复插电模式下的自动睡眠示例，例如 30 分钟：

```bash
sudo pmset -c sleep 30
```

也可以用 **Amphetamine** 等工具在 Kodi 运行或外接显示器连接时保持系统清醒，配置更直观，也更容易临时停用。

## 避免唤醒后再次登录

进入“系统设置 → 锁定屏幕”，检查“屏幕保护程序启动或显示器关闭后需要密码”的时间设置。

如果希望唤醒后直接回到 Kodi，可将其设为“永不”。但这会降低本地安全性：任何能接触 Mac 的人都可直接访问当前账户。更稳妥的做法是为电视盒子单独创建一个不含私人资料的 macOS 标准账户。

另外检查：

- “系统设置 → 隐私与安全性 → 高级”中的闲置自动退出登录；
- 是否确实是系统睡眠、重启或用户注销，而不只是显示器关闭；
- Kodi 是否因为退出或崩溃而回到桌面。

不建议仅为免登录而关闭 **FileVault**。FileVault 主要影响开机前磁盘解锁和自动登录；正常的显示器唤醒是否要求密码，应优先通过锁定屏幕设置和独立电视账户解决。

## Kodi 自动启动

最简单的方式是将 Kodi 加入“系统设置 → 通用 → 登录项”。Kodi 内再设置全屏显示。

如果使用 `launchd` 的 `KeepAlive` 自动拉起 Kodi，需要注意：从 Kodi 菜单正常退出后也会被立即重新启动。维护或升级 Kodi 前，应先停用对应 LaunchAgent，避免反复拉起。

## 推荐组合

- **播放**：Kodi；平台投屏不兼容时改用 Mac 网页版或官方客户端；
- **Kodi 遥控**：Official Kodi Remote 或 Sybu；
- **全局 Mac 操作**：手机触控板类软件，或小型无线键盘；
- **关屏/亮屏**：iPhone 快捷指令通过 SSH 执行 `pmset displaysleepnow` 与 `caffeinate -u -t 2`；
- **防系统睡眠**：仅对交流电源设置 `sleep 0`，或使用 Amphetamine；
- **安全**：单独建立电视盒子账户，避免关闭 FileVault，也不要复用主账户密码。
