调研日期：2026-08-16

## 一、结论先行

将不同到期月份的期货数据聚合成“主连”，应拆成两个独立问题：

1. **合约映射（mapping）**：每个交易日到底选哪个真实合约。
2. **价格归一化（normalization / adjustment）**：换月时是否消除新旧合约之间的价差，以及如何消除。

建议系统同时保存以下四类数据，而不是只生成一根无法追溯的主连 K 线：

| 数据集 | 用途 | 是否可直接下单 |
| --- | --- | --- |
| 真实月份合约 | 原始事实、成交与回放 | 是 |
| 主力映射表 | 说明每日主连对应哪个真实合约 | 映射后才可以 |
| 不复权主连 | 真实价格、撮合、换月跳空 | 通过映射合约下单 |
| 后向比例复权主连 | 指标、收益率、趋势研究 | 否，价格是合成值 |

针对国内商品期货，推荐默认方案：

- 用 **T-1 日收盘后可知的持仓量** 决定 T 日主力；
- 候选新合约持仓量达到当前主力的 **1.1 倍**才切换；
- 只允许向更远交割月迁移，禁止旧合约重新成为主力；
- 临近最后交易日时设置强制换月兜底；
- 日内不切换，在新交易日（含其夜盘）开始时整日切换；
- 同时产出不复权和后向比例复权数据；
- 映射表、换月事件表、复权因子表单独持久化。

这与 RQData 默认规则接近，也比“每天直接选持仓量最大合约”稳定，能减少两个合约之间的反复切换。

## 二、主连、近月和指数连续

- **主力连续（dominant continuous）**：每天选择流动性最强的真实合约，常用持仓量、成交量或二者组合判断。
- **近月连续（front month）**：始终选择最近可交易交割月，到预设日期或到期时切换，不关心它是不是最活跃。
- **次主力 / 第 N 合约**：选择第二活跃合约，或沿期限结构向后偏移 N 档。
- **指数连续**：对同品种多个真实合约按持仓量等权重加权，不代表一张可直接成交的合约。
- **恒定到期（constant maturity）**：在相邻合约间按剩余期限插值，构造固定 30 天、60 天等到期敞口。

“主连”本质上是一个随时间变化的映射，不是交易所挂牌合约。

设交易日 `t` 的主力真实合约为 `M_t`，不复权主连为：

```text
P_raw(t) = P(M_t, t)
```

当 `M_t != M_(t-1)` 时，新旧合约因为期限、仓储、利率、季节性等原因通常价格不同。这个差异是真实期限结构，不是坏数据；但它会污染移动平均、动量和收益率计算，所以研究序列常需要复权。

## 三、主要项目与平台

### 3.1 QuantConnect LEAN

LEAN 对映射与归一化的分层最清楚，很适合作为架构参考。

**映射模式 `DataMappingMode`：**

- `LAST_TRADING_DAY`：近月到期前一日映射到下一合约；
- `FIRST_DAY_MONTH`：交割月第一天切换；若合约更早到期，则在最后交易日切换；
- `OPEN_INTEREST`：后月合约持仓量超过当前合约时切换；
- `OPEN_INTEREST_ANNUAL`：面向年度合约链的流动性映射模式。

**价格归一化 `DataNormalizationMode`：**

- `RAW`：不调整；
- `FORWARD_PANAMA_CANAL`：差值前向调整，最早合约保留真实价格；
- `BACKWARDS_PANAMA_CANAL`：差值后向调整，最新合约保留真实价格；
- `BACKWARDS_RATIO`：比例后向调整，最新合约保留真实价格。

`contract_depth_offset=0/1/2` 可选择当前映射合约、后一档、后两档。连续合约本身不可交易，订单必须发往 `mapped` 对应的真实合约；换月通过 `SymbolChangedEvent` 通知策略。

借鉴点：**连续序列 ID、映射后的真实合约 ID、合成价格三者明确分离**。

来源：[LEAN Futures 文档](https://www.quantconnect.com/docs/v2/writing-algorithms/universes/futures)

### 3.2 RQData / Ricequant

RQData 对中国期货的规则披露最具体，可作为国内主连的重要参照。

**默认主力规则：**

- 上市初期，以当日收盘同品种持仓量最大者作为下一交易日主力；
- 其他合约收盘持仓量超过当前主力 **1.1 倍**时，下一交易日切换；
- 日内不切换；
- 一个合约做过主力后不重复成为主力；
- 股指期货默认只在当月与次月中选择。

`futures.get_dominant` 还支持只按昨仓排名、要求昨日成交量与持仓量同时最大，以及排除最后交易日合约等规则。

**连续合约代码与调整：**

- `88`：简单拼接，不平滑；
- `888`：前复权，以切换前一日新旧合约收盘价差调整历史；
- `889`：后复权，以切换日新旧合约开盘价差调整未来；
- `99`：全部可交易合约按持仓量加权的指数连续。

新接口还支持 `pre/post/none`，以及 `prev_close_spread`、`open_spread`、`prev_close_ratio`、`open_ratio` 四类调整方法，并可单独查询复权因子。

借鉴点：**1.1 倍滞回阈值、次日生效、不可回切、显式复权因子表**。

来源：[RQData 期货行情与连续合约文档](https://www.ricequant.com/doc/rqdata/python/futures-mod)

### 3.3 Tushare

Tushare 的 `fut_mapping` 提供“连续合约代码 + 交易日 -> 真实月份合约”的映射，字段包括：

- `ts_code`：连续合约代码；
- `trade_date`：交易日期；
- `mapping_ts_code`：当日对应真实合约。

它适合用于交叉校验自建映射，但公开文档没有完整披露主力阈值和复权公式，不宜作为算法规范的唯一来源。

来源：[Tushare 期货主力与连续合约](https://tushare.pro/document/2?doc_id=189)

### 3.4 AKShare

AKShare 提供国内外期货行情和连续合约相关接口。文档中的国内主力说明与 RQData 的“持仓量最大、1.1 倍、次日切换”口径相近。

适合快速获取样本、做原型和交叉核验。若用于生产，应固定底层数据源与版本，并自行做完整性审计。

来源：[AKShare 期货数据文档](https://akshare.akfamily.xyz/data/futures/futures.html)

### 3.5 东财掘金 / EmQuant

`fut_get_continuous_contracts` 能查询连续合约每日对应的真实合约，并区分主力、次主力、前五个月份连续和加权指数合约。

其主力规则有较强的“成交量 + 持仓量”特征：

- 成交量和持仓量同时最大的合约成为新主力；
- 收盘结算后判断，下一交易日切换，日内不切换；
- 若当前主力两项都不再最大，金融期货按成交量最大选择，商品期货按持仓量最大选择。

这说明业内不存在唯一的“主力”定义。同一天，不同数据商的主连可能对应不同真实合约。

来源：[东财掘金期货基础数据函数](https://emquant.18.cn/help/doc/python/python_select_api_future.html)

### 3.6 Zipline / Zipline Reloaded

Zipline 的连续期货抽象支持 `root_symbol`、合约链 `offset`、日历或成交量换月，以及不调整、加法调整和乘法调整。它把连续合约作为资产层对象，在查询历史窗口时完成映射与调整。

借鉴点：主连不必预先拍扁为唯一一份 CSV，调用方可以选择 roll 与 adjustment 版本。

来源：[Zipline Reloaded API](https://zipline.ml4trading.io/api-reference.html)

### 3.7 Backtrader

Backtrader 的 `RollOver` feed 接受多个到期合约，并提供两个扩展点：

- `checkdate(dt, d)`：当前日期是否进入允许换月窗口；
- `checkcondition(d0, d1)`：是否满足换月条件，例如新合约成交量超过旧合约。

它擅长灵活拼接和回测，但默认示例主要是不复权拼接；价格归一化通常需要在预处理层另做。

借鉴点：把 **日期硬约束** 与 **流动性软条件** 组合，而不是只看一个排名字段。

来源：[Backtrader Rolling Futures](https://www.backtrader.com/docu/data-rollover/rolling-futures-over/)

### 3.8 NautilusTrader

NautilusTrader 的实现偏底层，适合分钟和实时数据。调用方明确传入一系列 transition，每条包括切换时间、新旧真实合约和切换两侧价格。引擎不负责发现主力，只负责按 transition 拼接和聚合。

支持：

- `BACKWARD_SPREAD`
- `FORWARD_SPREAD`
- `BACKWARD_RATIO`
- `FORWARD_RATIO`

它还要求 transition 时间严格递增、合约链首尾相接，并明确讨论换月落在未完成 K 线内部时的处理。

借鉴点：**主力发现器和行情聚合器解耦，切换事件是显式输入**。

来源：[NautilusTrader Continuous Futures](https://nautilustrader.io/docs/latest/concepts/continuous_futures/)

### 3.9 pysystemtrade

pysystemtrade 是完整的系统化期货工程。其数据流程大致是：

```text
真实合约价格 + roll 参数
  -> roll calendar
  -> multiple prices（PRICE / CARRY / FORWARD 及对应合约）
  -> adjusted prices
  -> 回测与生产交易
```

它把信号主价格、carry 合约和即将换入的 forward 合约并排保存。这比单列 `dominant_contract` 更适合跨期价差、期限结构和实盘换月。

借鉴点：**研究数据、carry 数据和持仓换月状态是不同对象**；roll calendar 可审计、可人工修订。

来源：[pysystemtrade](https://github.com/pst-group/pysystemtrade)、[Working with futures data](https://github.com/pst-group/pysystemtrade/blob/develop/docs/data.md)

### 3.10 Stitcher

Stitcher 是 Julia 工具：读取带 `Date/OHLC/Open_Interest/Contract` 的 CSV，每天选择持仓量最高合约，输出不复权拼接、换月日期、乘法或加法后向复权。

代码简单，适合验证算法；但“每天直接选最大持仓”缺少滞回与不可回切机制，生产使用前需要增强。

来源：[XilinJia/Stitcher](https://github.com/XilinJia/Stitcher)

### 3.11 Sierra Chart

Sierra Chart 提供日期规则换月、成交量换月，以及各自的后向复权版本。商品期货更推荐成交量换月，股指等规则明确的品种更适合日期换月。

新版后向调整使用 **换月日前一交易日的新旧合约结算价差**，而不是换月日开盘价差。分钟图在交易时段 `Start Time` 切换，夜盘场景可能落在自然日的前一天。

借鉴点：分钟数据不能只按自然日期拼接，必须按 **交易日 + session 起点** 处理。

来源：[Sierra Chart Continuous Futures](https://www.sierrachart.com/index.php?page=doc/ContinuousFuturesContractCharts.html)

## 四、换月规则比较

| 规则 | 优点 | 缺点 | 适合场景 |
| --- | --- | --- | --- |
| 固定到期前 N 个交易日 | 确定、可复现、无回切 | 不一定跟随真实流动性 | 股指、国债、规则稳定品种 |
| 后月成交量超过当前合约 | 跟随成交活跃度 | 噪声大，易受单日异常影响 | 海外成熟期货、日内关注品种 |
| 后月持仓量超过当前合约 | 稳定、代表资金迁移 | 比成交量变化慢 | 国内商品主力 |
| 成交量和持仓量同时最大 | 误切少 | 可能较晚才切换 | 数据商标准主连 |
| 流动性综合分数 | 可综合 volume/OI/spread | 参数多、解释更难 | 自研执行系统 |
| 多日线性加权换月 | 合成价格和仓位平滑 | 需要双合约交易，成本更高 | 可交易指数、组合净值模拟 |

### 推荐状态机

不要每天独立排名。对品种 `u`，交易日 `t` 的主力 `M_t` 应由有记忆的状态机产生：

```text
输入：截至 t-1 收盘可知的 volume、open_interest、expiry、上市状态
状态：M_(t-1)、历史已做过主力的合约、连续确认天数

1. 过滤未上市、已到期、无有效行情、进入交割限制区的合约。
2. 默认保持 M_t = M_(t-1)。
3. 只在到期月份晚于当前主力的候选中寻找新合约。
4. 若候选 OI >= 1.10 * 当前主力 OI，则标记切换。
5. 可选：要求连续 2 日满足，或同时满足最低成交量门槛。
6. 若当前主力距最后交易日 <= safety_days，强制切到合格后月。
7. 切换从 t 的 session 起点生效，整日不再改变。
8. 已退出的旧合约不得重新成为主力。
```

避免未来函数的关键是：**T 日映射只能使用 T-1 日收盘后已经确定的数据**。如果用 T 日最终成交量决定 T 日全日属于哪个合约，就是把收盘后才知道的信息倒灌到当天早盘。

## 五、价格调整方法

设切换边界新合约价格为 `P_new`，旧合约价格为 `P_old`。

### 5.1 不复权拼接

```text
P_cont(t) = P(M_t, t)
```

每个价格都真实可成交，但换月跳空会形成虚假收益和技术指标冲击。适合撮合、下单价格、成本和换月损益分析。

### 5.2 差值调整（Panama / spread）

```text
d = P_new - P_old
P_adj(t) = P_raw(t) + cumulative_future_differences(t)
```

后向调整让最新合约保持真实价格。它保留绝对点数变化，但长期历史可能漂移甚至为负，百分比收益也会失真。

### 5.3 比例调整（ratio）

```text
r = P_new / P_old
P_adj(t) = P_raw(t) * product_of_future_ratios(t)
```

它更好地保持百分比收益，适合趋势和动量研究。但历史绝对价格、tick size、涨跌停和阈值不再真实；参考价格非正时不能使用。

### 5.4 多日加权 / perpetual series

在 `N` 个换月日内，让旧合约权重从 1 降到 0，新合约从 0 升到 1：

```text
P_t = w_t * P_old,t + (1 - w_t) * P_new,t
```

这不是复权，而是模拟持仓逐步迁移。只有回测也按相同权重持有两张合约时，收益才可实现。

来源：[QuantStart 方法比较](https://www.quantstart.com/articles/Continuous-Futures-Contracts-for-Backtesting-Purposes/)、[ArbitrageLab Futures Rollover](https://hudson-and-thames-arbitragelab.readthedocs-hosted.com/en/latest/data/futures_rollover.html)

### 5.5 切换参考价格

常见定义：

- `prev_close_spread`：T-1 日新旧合约收盘价差；
- `prev_settlement_spread`：T-1 日新旧合约结算价差；
- `open_spread`：T 日新旧合约开盘价差；
- 对应的 close/open ratio。

默认推荐 **T-1 同时可见的新旧合约结算价或收盘价**：两个价格来自同一时点，映射在 T 日 session 前即可确定，也不必等待两个合约都形成有效开盘价。

如果回测模拟 T 日开盘换仓，应另外记录旧合约平仓价、新合约开仓价和交易成本，不能拿复权差值代替换月损益。

## 六、分钟与 Tick 数据

### 6.1 交易日不是自然日

国内期货夜盘通常属于下一交易日。主力映射键应使用 `trading_date`，不能直接使用时间戳的自然日期。原始记录至少保存：

```text
exchange_timestamp
trading_date
session_id
symbol
```

### 6.2 整个交易日只映射一个主力

如果 T-1 收盘后确认 T 日切换，那么 T 日夜盘开始即使用新合约。不要在日盘开盘再切一次，也不要依据 T 日盘中成交量回写早先分钟。

### 6.3 日线与分钟线对账

两种路径都可行：

1. 先按真实合约生成日线，再按映射表选择；
2. 先按 `trading_date` 选择主连分钟，再聚合日线。

只要 session、缺失值和切换时点一致，结果应相同。建议路径 1 作为权威日线，路径 2 作为一致性测试。

### 6.4 不要先拼累计字段再做差

Tick 中当日累计成交量、成交额在不同合约中基准不同。必须先在每个真实合约内部做差生成增量，再选择主力分钟；否则换月边界会产生巨大伪增量。

### 6.5 缺失分钟不能随便从另一合约补

当前主力某分钟无成交时，要区分“无成交”和“无数据”。除非产品定义明确允许，否则不能临时拿次主力价格填充，这会让同一交易日暗中混入多个合约。

## 七、建议数据模型

### 7.1 合约元数据 `futures_contract`

```text
exchange, root_symbol, contract_symbol, listed_date, last_trade_date,
delivery_month, multiplier, price_tick, session_template_id
```

### 7.2 流动性快照 `contract_daily_liquidity`

```text
trading_date, contract_symbol, volume, open_interest, turnover,
days_to_expiry, valid_bar_count, source_version
```

### 7.3 主力映射 `continuous_mapping`

```text
continuous_id, trading_date, mapped_contract,
decision_date, rule_id, rank, previous_contract,
switch_flag, switch_reason, input_snapshot_version
```

`decision_date` 通常应为前一交易日，这是未来函数审计的关键字段。

### 7.4 换月事件 `roll_event`

```text
continuous_id, effective_trading_date, effective_timestamp,
old_contract, new_contract, trigger_type,
old_oi, new_oi, old_volume, new_volume,
old_reference_price, new_reference_price,
spread_factor, ratio_factor, rule_version
```

### 7.5 连续行情

至少生成：

```text
continuous_raw_1m
continuous_back_ratio_1m
continuous_raw_1d
continuous_back_ratio_1d
```

每根 bar 保留 `mapped_contract`、`adjustment_factor` 和 `rule_version`。成交量、持仓量不做价格复权；成交额是否保留要谨慎，因为复权价格与原始成交额不再同口径。

### 7.6 版本化

交易所补数据、供应商修订持仓量、规则升级都可能改变历史映射。输出应由以下版本共同标识：

```text
raw_data_version + calendar_version + mapping_rule_version + adjustment_version
```

不要静默覆盖历史结果。

## 八、推荐实现流程

```text
1. 导入并清洗每个真实月份合约的 Tick/1m 数据
2. 按交易日生成真实合约日线和流动性快照
3. 用 T-1 快照运行主力状态机，生成 T 日 mapping
4. 生成 roll_event，保存新旧合约同一参考时点价格
5. 按 mapping 选择原始 1m/1d，生成不复权主连
6. 从 roll_event 计算累计 spread/ratio 因子
7. 只调整 OHLC/settlement 等价格字段，生成研究序列
8. 用主连分钟重聚合日线，与真实合约日线对账
9. 输出映射变化、跳空、缺失 bar、异常因子的审计报告
```

建议默认配置：

```yaml
mapping:
  signal_lag_sessions: 1
  primary_metric: open_interest
  switch_ratio: 1.10
  confirmation_days: 1
  direction: forward_only
  allow_reentry: false
  expiry_safety_days: 5
  switch_at: trading_session_start

adjustment:
  research_default: backward_ratio
  reference: previous_settlement
  preserve_latest_contract_price: true
  adjust_fields: [open, high, low, close, settlement]
  do_not_adjust: [volume, open_interest]
```

`expiry_safety_days` 应按品种配置，不能所有交易所一刀切。进入交割月限制、客户类型持仓期限、保证金和流动性衰减都需要纳入品种规则。

## 九、验证清单

1. **无未来函数**：`decision_date < effective_trading_date`。
2. **单向迁移**：除代码变更等特殊事件外，交割月不倒退。
3. **无回切**：退出过的旧合约不再成为主力。
4. **日内稳定**：同一 `trading_date` 只有一个 `mapped_contract`。
5. **合约有效**：映射合约当日已上市且未过最后交易日。
6. **原始可追溯**：任意 bar 能还原到真实合约原始记录。
7. **复权连续性**：换月边界按选定公式后的理论跳空接近 0。
8. **OHLC 合法**：复权后仍满足 `low <= open/close <= high`。
9. **比例有效**：ratio 模式参考价格严格为正。
10. **分钟/日线一致**：主连分钟聚合日线与主连日线一致。
11. **数据商对照**：抽样与 RQData、Tushare 或东财映射比较，差异可解释。
12. **换月损益独立**：持仓换月使用真实成交价和手续费，不使用复权价成交。

## 十、最终建议

国内期货研究的第一版，建议至少提供：

- `dominant_raw`：持仓量 1.1 倍阈值、T+1 生效、不复权；
- `dominant_back_ratio`：同一映射，T-1 结算价比例后向复权；
- `front_month_raw`：按到期规则切换，用于期限结构对照；
- 完整的 `mapping`、`roll_event`、`adjustment_factor` 三张审计表。

交易信号优先使用后向比例复权序列；委托、撮合、止损价、合约乘数和成本始终回到映射后的真实合约与原始价格。carry、展期收益和期限结构策略应直接使用同时期多个真实月份合约，不要只依赖主连。

最重要的一条：**主连是研究视图，真实合约才是交易事实。**
