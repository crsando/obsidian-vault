## 核心结论

大模型本身**不会"上网"**。所谓"联网搜索"不是模型内部能力，而是外面套了一层**工具调用（Tool Calling / Function Calling）**机制：模型判断训练数据里没有、需要实时信息时，不直接回答，而是吐出一个结构化"工具调用"指令，由**应用层**执行搜索，再把结果喂回模型，让模型基于结果生成带引用的回答。

一句话：**联网搜索 = 工具调用 + 搜索引擎 API + RAG 回填**。难点不在"会搜"，而在工程化——搜索质量、去重、引用溯源、多轮反思循环、成本控制。

## 核心五步数据流

1. **模型判断**：收到问题，判断训练知识不足、需要实时信息。
2. **输出 Tool Call**：吐出结构化 JSON（要搜什么、几个查询词）。
3. **应用层执行**：调搜索引擎 API（Bing / Google / Tavily / DuckDuckGo 等）。
4. **结果回填**：标题 + 摘要 + URL 塞回上下文（可能还要抓正文）。
5. **带引用生成**：模型基于结果作答，并标注引用来源。

## 两条主流实现路线

### 路线 A：官方内置 Web Search 工具（闭源大厂）

- OpenAI / Google / Claude 都在 API 里内置了 `web_search` 工具，背后接 **Bing / Google 搜索 + 自家爬虫**，用户看不到搜索引擎这层。
- OpenAI 现在分**三档**（典型分层）：
  1. **普通搜索**：不推理，模型直接把用户问题转成搜索词丢出去，最快。
  2. **Agentic Search**：推理模型把"搜索"放进思维链里，搜一次 → 看结果 → 决定要不要再搜、换词搜，适合复杂问题。
  3. **Deep Research**：跑几分钟、上百个来源，专门做长报告。
- 关键控制参数：
  - `search_context_size`：给模型看多少搜索结果。
  - `filters`：限定 / 屏蔽域名。
  - `sources`：完整来源列表。
  - `citation annotations`：内联引用标注。

### 路线 B：自己搭 RAG 搜索增强（开源 / 国内主流）

- 这是 **DeepSeek、Qwen** 这类**开源模型**真正用的路子——**DeepSeek 官方 API 不提供联网搜索**，只有网页版 / App 有"联网"开关。
- 标准搭法：搜索 API（Tavily / SearxNG / Brave / DuckDuckGo / Bing）→ 抓取正文 → 切块 → 检索 → 拼进 prompt。
- 社区玩 DeepSeek R1 联网，基本都这么搭（如 Open WebUI 里选 DDG / Brave 作为搜索后端）。

## 深度调研（Deep Research）是多 Agent 架构

不是"多搜几次"这么简单，而是分角色的流水线：

- **Planner**：把大问题拆成若干子问题 / 研究问题。
- **Crawler 群**：多个爬虫 Agent 并行搜每个子问题。
- **摘要 + 溯源**：每个来源做摘要，并保留来源追踪。
- **Publisher**：过滤去重、汇总成一篇带引用的报告。

开源代表：

- **GPT Researcher**：planner + execution + publisher 三件套，受 STORM 论文启发。
- **browser-use**：让 LLM 像人一样操控真实浏览器去点、填、翻页。
- **Perplexity**：本质上也是"搜索 + RAG + 引用"的答案引擎，做了极致的工程化和产品化。
