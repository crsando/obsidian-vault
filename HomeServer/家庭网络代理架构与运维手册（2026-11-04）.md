> [!success] 当前状态（2026-11-04 11:20）

## 1. 整体架构

```
主路由（中兴 192.168.5.1）
  ├─ DHCP 下发 DNS：223.5.5.5 / 119.29.29.29（全局统一）
  └─ 网关按设备下发：需要代理的 → 192.168.5.5；不需要的 → 192.168.5.1

旁路由（NanoPi R4S · 192.168.5.5 · Armbian / kernel 6.18.44）
  └─ ShellCrash（只负责启停 + 下发 iptables）
       └─ mihomo v1.19.17 · Tproxy · iptables
```

### DNS 为什么不能指向旁路由

DNS 设成 192.168.5.5 其实也能分流，但旁路由一挂全网解析就断。所以下发外部 DNS（223.5.5.5），靠 iptables 把局域网发往**任何地址**的 53 端口流量劫持到 mihomo 的 1053，旁路由挂了还能直连上网：

```
客户端 → 223.5.5.5:53
  → 网关是 5.5，包先到旁路由
  → iptables nat shellcrash_dns: -s 192.168.5.0/24 -p udp -j REDIRECT --to-ports 1053
  → mihomo fake-ip（境外域名返回 198.18.x.x，国内域名返回真实 IP）
```

副作用：浏览器自带 DoH、系统 DoT 会绕过这个劫持，**必须在设备上关掉**。

## 2. 三种流量路径

| 类型 | 路径 |
|---|---|
| 普通境外 | TPROXY:7893 → 规则 → `Proxy` 组（新加坡优先 / 香港兜底）→ 机场 trojan |
| AI 服务 | → `AI` 组 → 硅谷 vmess，第一跳由 `dialer-proxy: Proxy` 决定（新加坡/香港 → 硅谷两跳） |
| Google 全家 | → `Google` 组（默认 Proxy 新加坡，可整体切 AI） |
| 国内 | iptables `-m set --match-set cn_ip dst -j RETURN` → **内核直接放行，不进 mihomo** |

> [!warning] 国内流量进不了 mihomo
> `cn_ip_route=ON` 让国内 IP 在 iptables 层就被放行。所以"某台机器国内也走美国"在旁路由层面做不到，必须在客户端装 Clash Verge 之类的工具。

## 3. 分组设计

| 组 | 类型 | 内容 | 用途 |
|---|---|---|---|
| `Proxy` | select | 新加坡优先 / 新加坡 / 香港 / 任意单节点 | 普通流量出口 |
| `AI` | select | 硅谷-链式 / Proxy | AI 服务，默认链式到硅谷 |
| `Google` | select | Proxy / AI | **Google 全家统一出口，默认 Proxy（新加坡）** |
| `♻️ 新加坡优先` | fallback | 新加坡 → 香港 | — |
| `🇸🇬 新加坡` / `🇭🇰 香港` | url-test | 按机场节点名过滤 | — |

规则顺序（命中即停）：局域网 → 自定义直连 → STUN → **Google（2 条 RULE-SET）** → AI → 国内直连 → `MATCH,Proxy`。

> [!note] Google 组是 2026-11-04 新增
> 之前 `gemini.google.com` 等 12 条走 AI（美国），其余 Google 走 Proxy（新加坡），同一个 Google 账号从两个国家 IP 出去。现在用 `google.mrs`（1078 条）+ `google-gemini.mrs`（49 条）统一到 `Google` 组，规则放在 AI 段**之前**（否则 gemini 先命中 AI）。

## 4. 关键实测数据

| 场景 | 结论 |
|---|---|
| 硅谷 vmess 直连 vs 链式 | 直连下载 **16 KB/s**（被限速），链式 **2.8 MB/s** → 必须链式 |
| alma.now 直连 vs 代理 | 直连落 Cloudflare LHR/AMS，1.3~3.8 s；香港 0.3 s → 走代理 |
| Alma 更新下载 | 直连 0.45 MB/s（15 分钟+）；经新加坡 12.7 MB/s；经香港 32 MB/s |
| 节点加载空窗 | 带 `use:` 的组在启动后 5~10 秒内只有 `COMPATIBLE`（等于直连） |

## 5. 运维命令

```bash
# 状态（只读）
ssh root@192.168.5.5 'bash ~/mihomo_deploy_v1/status.sh'

# 改规则：改文件 → 热重载（国外网断 5~10 秒，失败自动回滚）
nano /etc/ShellCrash/yamls/config.yaml     # ⚠️ 不要改 /etc/ShellCrash/config.yaml，那是软链接
bash ~/mihomo_deploy_v1/reload.sh

# 只刷新订阅节点（不断网）
S=$(cat ~/mihomo_deploy_v1/.secret)
curl -X PUT -H "Authorization: Bearer $S" http://127.0.0.1:9999/providers/proxies/airport

# 面板
# http://192.168.5.5:9999/ui   密码：cat ~/mihomo_deploy_v1/.secret

# 本机验证
bash ~/src/home-network/01-mihomo-shellcrash/verify-mac.sh
```

## 6. 五个坑（都踩过）

1. **`/etc/ShellCrash/config.yaml` 是软链接**，链条是 `→ /tmp/ShellCrash/config.yaml → yamls/config.yaml`。用 `sed -i` 或编辑器改它会把链接替换成普通文件，改动等于白改。**只改 `yamls/config.yaml`。**
2. **面板密码要在两处同时设**：`yamls/config.yaml` 的 `secret` 和 `configs/ShellCrash.cfg` 的 `secret`。ShellCrash 启动时会带着 cfg 里的密码调 API 检测内核，只设一处会被判成启动失败。
3. **空组等于直连**：带 `use:` 的组在节点加载前只有一个 `COMPATIBLE`，效果是 DIRECT。旁路由重启后有 5~10 秒处在这个状态。
4. **机场订阅会间歇性返回 403**：靠本地 `providers/airport.yaml` 缓存冷启动，别删这个文件。
5. **不要开 IPv6**：全网不用，`ipv6: false`，AAAA 查询返回空。
